🔍 Detailed Problem Analysis Table (12 Defects Identified & Fixed)

Each problem is explained from the user's perspective (screen reader users, mobile touchscreen users, keyboard navigators, and data integrity). For Problems #3 and #11, two valid alternate solutions are provided with engineering rationale for the chosen method.

# Line of Code Why It Is a Problem for the User How We Fixed It & Alternatives
1 <input type="text" placeholder="Your name"> Missing <label> and name attribute. Placeholder text disappears immediately when user starts typing, burdening short-term memory. Screen readers cannot announce the purpose of the field. Without a name attribute, the value is omitted from HTTP form submission payload. Added dedicated <label for="resName">Your Name</label> and set id="resName" name="customerName" required autocomplete="name".
2 <input type="text" placeholder="Email"> Incorrect input type and missing label. Using generic type="text" prevents mobile devices from displaying the email-optimized keyboard (containing @ and .com). Native browser email syntax validation is also bypassed. Changed to type="email", added <label for="resEmail">, id="resEmail" name="customerEmail" required autocomplete="email".
3 <label>Phone</label>
<input type="text" id="phone"> 		Unlinked label and wrong input type. The label lacks the for="phone" attribute, so clicking the text "Phone" fails to activate/focus the input box (harms users with tremors or mobile touch). type="text" does not trigger the numeric dialpad on smartphones. Chosen Fix: Added for="resPhone" attribute to label, changed input to type="tel" name="customerPhone" autocomplete="tel" required.
💡 Alternative Fix: Wrap the input inside the label: <label>Phone <input type="tel"...></label>.
Why we chose the explicit for/id approach: Bootstrap 5 grid layout and .form-label styling work reliably and cleanly with separated elements without causing flex/grid CSS conflicts.
4 <label for="guests">Guests</label>
<input type="text" id="people"> 		ID mismatch between label and input! The label references for="guests" while the input possesses id="people". Assistive technology fails to connect the label to the control. User clicking "Guests" does nothing. Also, type="text" permits entering invalid non-numeric characters. Synchronized IDs: for="resGuests" matching id="resGuests". Changed to type="number" min="1" max="30" step="1" name="guestsCount" required.
5 <label for="date">Date</label>
<input type="text" id="date" placeholder="dd/mm/yyyy"> 		Generic text input for dates and duplicate ID danger. Users must manually type dates in exact format, leading to frequent formatting errors (e.g. 10/11 vs 11/10). No datepicker popup. Missing name attribute. Moreover, the ID date is reused below! Changed to type="date", assigned unique id="resDate", connected <label for="resDate">, added name="reservationDate" required.
6 <input type="radio" name="inside" id="date"> Inside
<input type="radio" name="terrace"> Terrace 		Broken radio group, duplicate ID, and missing option labels. 1) Different name attributes (name="inside" vs name="terrace") prevent mutual exclusion; both or neither can be checked simultaneously.
2) Duplicate id="date" breaks HTML specification and W3C validation.
3) Text labels "Inside" and "Terrace" are bare text without <label for="...">, forcing users to hit tiny 16px radio circles on touchscreen phones. 		Unified name="seatingPreference" for both radio inputs, assigned unique IDs id="seatingInside" and id="seatingTerrace", wrapped text in <label class="form-check-label" for="...">, added explicit values.
7 <p>Seating:</p> Unsemantic group heading. A paragraph tag provides no programmatic connection to the radio group. Screen readers read "Seating" as isolated text, giving no context when navigating between radio items. Replaced with semantic <fieldset><legend class="form-label...">Seating Preference</legend>...</fieldset>, ensuring screen readers announce the group question.
8 <select>
<option>Lunch</option>
<option>Dinner</option>
</select> 		Missing label, missing name, missing option values. Completely unlabeled dropdown is an accessibility failure (WCAG 2.1). Without a name attribute, chosen option is lost during form submit. Added <label for="resMealSlot">Meal / Time Slot</label>, id="resMealSlot" name="mealSlot" class="form-select" required, and explicit value="Lunch" and value="Dinner".
9 <textarea placeholder="Comments"></textarea> Missing label, missing id, missing name. Disappearing placeholder is inaccessible to screen readers and visually impaired users. Data typed here cannot be sent to the server. Added <label for="resComments">Comments & Dietary Requests</label>, id="resComments" name="customerComments" class="form-control" rows="3".
10 <input type="checkbox"> I agree to the terms Unlinked checkbox label, missing name, missing required. Users cannot click the agreement text to toggle the checkbox. Extremely frustrating on smartphones. Also missing name="termsAgreement" and required. Created proper Bootstrap .form-check structure: <input type="checkbox" class="form-check-input" id="resTerms" name="termsAgreement" required> with <label class="form-check-label" for="resTerms">.
11 <div class="btn btn-primary">Reserve</div> Non-functional fake button! (Critical Blocker). A <div> is not focusable via keyboard Tab, cannot be pressed with Enter or Space, has no ARIA role, and NEVER submits the form! Data is never sent to the café server. Chosen Fix: Replaced with genuine HTML <button type="submit" class="btn btn-primary rounded-pill px-5 fw-bold">Reserve Table</button>.
💡 Alternative Fix: Use <input type="submit" value="Reserve Table" class="btn btn-primary">.
Why we chose <button type="submit">: The <button> element is much more extensible, allows nested HTML (icons, spinners), matches standard Bootstrap 5 best practices, and behaves reliably across all browsers.
12 <form> Missing action and method attributes. Without action and method="post", submission defaults to GET and appends potential sensitive customer information to the browser URL string. Added action="#" method="post" with appropriate semantic attributes.
