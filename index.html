Table of Problems (Found & Fixed)

# Line of code Why it is a problem for the user How you fixed it
1 <input type="text" placeholder="Your name"> Missing label and name. Placeholder disappears when typing, screen readers cannot identify field, and name data is omitted on submission. Added <label for="tab3Name">Your Name</label> and id="tab3Name" name="customerName" required autocomplete="name".
2 <input type="text" placeholder="Email"> type="text" does not bring up email keyboard with '@' key on mobile; browser email validation is disabled; missing label and name. Changed to type="email", added connected label and name="customerEmail" required.
3 <label>Phone</label>
<input type="text" id="phone">		 Label lacks for="phone", so clicking 'Phone' does not focus the input. type="text" does not show numeric telephone keypad. How fixed: Added for="tab3Phone", set type="tel" name="phone" required.
Alternative fix: Nest input inside label: <label>Phone <input type="tel"...></label>.
Why chosen: Bootstrap 5 styles and responsive grid work cleanest when label and control are separate elements.
4 <label for="guests">Guests</label>
<input type="text" id="people">		 ID mismatch! Label points to 'guests' but input ID is 'people'. Clicking label fails. type="text" allows letters instead of numbers. Synchronized IDs: for="tab3Guests" matching id="tab3Guests". Changed to type="number" min="1" max="30" step="1" name="guests" required.
5 <label for="date">Date</label>
<input type="text" id="date" placeholder="dd/mm/yyyy">		 Manual date typing leads to format mistakes; no datepicker; ID 'date' is duplicated in the radio button below! Changed to type="date", assigned unique id="tab3Date" with connected label, added name="date" required.
6 <input type="radio" name="inside" id="date"> Inside
<input type="radio" name="terrace"> Terrace		 Different names prevent mutual exclusion (user can select both or neither). Duplicate ID 'date'. Missing <label> tags. Unified name="seating" for both radios, gave unique IDs, added proper labels and values.
7 <p>Seating:</p> Unsemantic paragraph gives no programmatic association to the radio options for screen reader users. Replaced with semantic <fieldset><legend class="form-label...">Seating:</legend>...</fieldset>.
8 <select>...</select> Unlabeled dropdown violates WCAG 2.1 accessibility. Missing name attribute causes data to be lost during submission. Added <label for="tab3Meal">Meal</label>, id="tab3Meal" name="meal" required, and explicit option values.
9 <textarea placeholder="Comments"></textarea> Missing label, missing id, missing name. Text entered cannot be identified by screen readers or sent to the server. Added <label for="tab3Comments">Comments</label>, id="tab3Comments" name="comments" rows="3".
10 <input type="checkbox"> I agree to the terms Unlinked label. Users cannot click text to toggle checkbox. Missing name and required attribute. Structured with Bootstrap .form-check: <input type="checkbox" class="form-check-input" id="tab3Terms" name="terms" required> and <label for="tab3Terms">.
11 <div class="btn btn-primary">Reserve</div> A <div> cannot receive keyboard focus via Tab, cannot be pressed with Enter, and NEVER submits the form! Data is never sent. How fixed: Replaced with genuine HTML <button type="submit" class="btn btn-primary rounded-pill px-5 fw-bold">Reserve</button>.
Alternative fix: Use <input type="submit" value="Reserve" class="btn btn-primary">.
Why chosen: <button> is more flexible, supports child HTML/icons, and is Bootstrap 5 recommended practice.
12 <form> Missing action and method attributes. Defaults to GET, exposing customer reservation parameters in the browser URL. Added action="#" method="post".
